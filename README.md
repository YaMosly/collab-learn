## Технологический стек

### Backend
- **Go** - Бэкенд
- **Chi Router** - Легковесный HTTP-роутер
- **Gorilla WebSocket** - Двунаправленная связь в реальном времени
- **PostgreSQL** - Надежное хранение данных
- **Redis** - Pub/Sub для синхронизации в реальном времени и кеширования

### Frontend
- **CodeMirror 5** - Редактор кода с подсветкой синтаксиса
- **Vanilla JavaScript** - Без зависимостей от фреймворков
- **Modern CSS** - Кастомные свойства, анимации и градиенты

CodeMirror 5.65.2, тема и используемые addons поставляются в приложении:
редактор не загружает код/CSS с CDN. Шрифты используют системный fallback.
Сведения об источнике, лицензии и воспроизводимой поставке —
в [web/static/vendor/README.md](web/static/vendor/README.md).
Это убирает внешние зависимости интерфейса, но для открытия/сохранения доски
по-прежнему нужен доступ к серверу. Внешние ресурсы из пользовательского preview
могут загружаться по сети.

## Быстрый старт

### Требования
- Docker & Docker Compose
- Git

### Установка

1. **Клонируйте репозиторий**
```bash
git clone https://github.com/YaMosly/collab-learn.git
cd collab-learn
```

2. **Создайте конфигурацию**
```bash
cp .env.example .env
```

В PowerShell: `Copy-Item .env.example .env`. Укажите свой `DB_PASSWORD` в `.env`;
без него запуск остановится с понятной ошибкой. Файл `.env` исключён из Git и Docker-образа.

3. **Запустите с помощью Docker Compose v2**
```bash
docker compose up --build -d --wait
docker compose ps
```

4. **Откройте в браузере**
```
http://localhost:8080
```

По умолчанию приложение доступно только на этом компьютере. PostgreSQL и Redis
не публикуют порты на хост. Для доступа по сети задайте `APP_BIND_ADDRESS`;
доски доступны по ссылке, без учётных записей. Для HTTPS-прокси задайте
`PUBLIC_ORIGIN`, например `https://learn.example.org`, и настройте HTTPS на прокси.

Данные PostgreSQL остаются в Docker volume при `docker compose down`.
Если volume уже существует, используйте его текущий пароль: изменение `.env`
не меняет пароль пользователя существующей базы. Не удаляйте volume ради смены пароля.
После изменения исходников повторите запуск с `--build`: файлы frontend теперь
входят в образ, локальная папка не подменяет их автоматически.

## Предпросмотр и проверки

Предпросмотр предназначен для HTML/CSS. Он работает в изолированном iframe:
скрипты из кода доски, формы, всплывающие окна и доступ к странице редактора запрещены.
Внешние картинки и CSS могут загружаться по сети; sandbox не делает их офлайн.

Проверки клиентской логики (Node.js 22+):

```bash
node --test tests/*.test.cjs
node --check web/static/js/app.js
```

Проверки Go:

```bash
go test ./...
go vet ./...
```

Тесты Node проверяют политику iframe, формирование документа и согласование
черновиков; они не заменяют проверку браузера и настоящей PostgreSQL.

## Доступ по ссылке

Общий каталог досок удалён: `GET /api/boards` больше не выдаёт данные.
Главная страница показывает до 20 недавно открытых досок из `localStorage`
этого браузера. Хранятся только ID и время открытия, без HTML/CSS. Кнопка очистки
удаляет локальный список, сами доски остаются в базе. При запрете хранилища
доску можно открыть по ссылке; сохраните её самостоятельно.

ID доски — случайный UUID v4. Любой, у кого есть полная ссылка, может читать
и редактировать документ. Это режим без публичного каталога, без ролей,
паролей и отзыва приглашений. Существующие ID не меняются: удаление каталога
не отзывает ссылки, которые кто-то уже получил. История браузера общая для его
профиля, поэтому на общем компьютере её можно очистить после работы.

Адрес для обмена имеет вид `/#board=<id>`. Старые `/?board=<id>` поддерживаются
и заменяются в адресной строке на фрагмент. Внутренние переходы также используют
совместимый query для полной загрузки документа. Приложение отправляет
`Referrer-Policy: no-referrer` и записывает в access log шаблон маршрута без ID
и query. API всё ещё содержит ID в пути: отдельно настройте журналы вашего прокси
и не публикуйте их вместе со ссылками.

HTTP API и WebSocket принимают браузерный Origin только от своего сайта.
Без `PUBLIC_ORIGIN` сравниваются фактические схема и Host запроса;
за HTTPS-прокси укажите точный внешний origin без завершающего `/`.
Произвольный CORS отключён. Native-клиенты без Origin продолжают работать:
проверка Origin не заменяет авторизацию и не защищает от обладателя ссылки.

Лимиты общие для экземпляров сервера, на фактический IP соединения:

| Запросы | Лимит за 60 секунд |
|---------|-------------------|
| Все HTTP API, включая handshake WebSocket | 6000 |
| Создание досок (дополнительно) | 30 |
| Handshake WebSocket (дополнительно) | 120 |

Превышение возвращает 429 с `Retry-After`. API возвращает 503 при недоступности
Redis, чтобы отказ ограничителя не открывал неограниченный доступ; health endpoints
остаются доступны. Ошибки 408/429 считаются временными, черновик сохраняется в
текущей вкладке. WebSocket принимает максимум 10 незапрошенных data-сообщений
в минуту на соединение; ping/pong этим лимитом не ограничены.

`X-Forwarded-For`, `X-Real-IP` и forwarded-схема не считаются доверенными.
За прокси пользователи делят лимит его IP; за NAT — своего внешнего IP.
Для публичного сервиса дополнительно настройте ограничения на прокси.

### Восстановление соединения

Ожидание открытия WebSocket ограничено 10 секундами; HTTP-запрос вместе с чтением
тела — 15 секундами. Повторное подключение использует задержку с jitter до 36 секунд.
При 429/503 клиент учитывает `Retry-After` (секунды или стандартную HTTP-date)
и не отправляет новые API-запросы/handshake раньше этого срока. Кнопки повтора
показывают оставшуюся паузу; ручной повтор и возврат вкладки её не обходят.
При недоступном/некорректном заголовке остаётся обычный backoff.

После возвращения сети или видимой вкладки открытое соединение сверяет документ
с сервером; прерванное — переподключается. Неподтверждённые правки остаются в
черновике вкладки. Поздняя ошибка запроса из прошлого соединения не закрывает
новое: неизвестный результат записи восстанавливается через проверку revision.

Ошибки открытия/создания отображаются внутри страницы. Временную ошибку открытия
можно повторить, не теряя адрес доски; при 403/404 предлагается проверить доступ/ссылку.
Создание доски не повторяется автоматически: потерянный ответ не доказывает,
что сервер ничего не создал. При недоступном буфере обмена кнопка Share показывает
ссылку для ручного копирования. Если загрузка файлов редактора не удалась,
сообщение предлагает перезагрузить страницу.

## Панели редактора

При ширине до 1024px показывается одна панель с вкладками HTML, CSS и Preview.
По вкладкам можно перемещаться стрелками ←/→, а Home/End выбирают первую/последнюю.
Tab переводит фокус в выбранную панель.

На широком экране границы панелей можно перетаскивать. С фокусом на границе
стрелки меняют ширину, Shift увеличивает шаг, Home/End выбирают крайнее допустимое
положение. Двойной щелчок возвращает равные размеры. Минимальная ширина панели —
240px. Текст, курсор и Undo сохраняются при переключении вкладок и размеров окна;
сами экземпляры редакторов остаются прежними.

Сохранение, экспорт, ошибки и выбор версии при конфликте остаются над панелями.
Если элементы не помещаются по высоте, страницу можно прокрутить.

## Локальный экспорт

В открытой доске доступны «Скачать HTML» и «Скачать CSS». Каждая кнопка скачивает
текущий текст соответствующего редактора в `collablearn.html` или `collablearn.css`,
включая неподтверждённые правки и локальную версию конфликта. Скачивание работает
при отсутствии связи и недоступном `sessionStorage`; запрос к серверу не требуется.

Экспорт использует UTF-8 и сохраняет полученный из редактора текст, включая пустой документ.
HTML экспортируется без добавления оболочки или ссылки на CSS; файлы скачиваются
отдельно. Экспорт не подтверждает сохранение на сервере, не снимает конфликт
и не удаляет черновик. Сообщение сообщает о передаче файла браузеру — проверьте
список загрузок. Временный Blob URL освобождается через минуту, при ошибке — сразу.

## Сохранение и конфликты

У каждого документа есть `revision`. Изменения сохраняются через HTTP PUT
с `base_revision`; WebSocket доставляет уведомления о новых версиях.
Сервер подтверждает запись после обновления PostgreSQL. Устаревшая запись
получает HTTP 409 с актуальным документом, не перезаписывая его.

- Параллельные изменения разных полей (HTML и CSS) объединяются автоматически.
- При изменениях одного поля локальная версия остаётся в редакторе,
  серверная — в панели конфликта. Выбор пользователя снова проходит проверку версии.
- До подтверждения сервера черновик хранится в `sessionStorage` текущей вкладки.
  Он переживает обновление страницы, но не гарантированно закрытие вкладки или браузера.
  При запрете хранилища показывается предупреждение.
- После восстановления WebSocket клиент получает свежий снимок HTTP и согласует
  черновик с ним. До подтверждения записи статус «Сохранено» не показывается.
- Лимит тела HTTP-записи — 512 КиБ. При ошибке черновик остаётся доступен.

Пример PUT `/api/boards/<id>`:

```json
{"base_revision": 0, "code_html": "<h1>Hello</h1>", "code_css": "h1 { color: teal; }"}
```

Отсутствующие/null-поля и старые WebSocket-записи не принимаются. После обновления
сервера обновите страницы участников: новый frontend и backend нужно развёртывать
вместе. Это контроль конфликтов на уровне полей, а не CRDT/OT для одновременного
посимвольного редактирования.

При запуске автоматически выполняется идемпотентная миграция
`migrations/002_board_revision.sql`; сбой обязательной миграции прерывает запуск.
Получение документа читает PostgreSQL напрямую, чтобы при reconnect не использовать
устаревший Redis-кэш.

### Несколько экземпляров сервера

Каждый экземпляр подтверждает общие Redis-подписки до начала приёма HTTP-запросов.
Они охватывают и доски, созданные после запуска. Локальная доставка не ждёт Redis;
повторные и устаревшие уведомления отбрасываются по revision отдельно для доски.

Redis Pub/Sub не хранит историю. После переподключения подписки WebSocket-клиенты
переподключаются и запрашивают актуальный документ. Дополнительно каждые 30 секунд
сервер предлагает фоновую сверку через HTTP, чтобы восстановиться после пропущенного
уведомления без перезапуска редактора.

Счётчик участников общий для экземпляров. Каждое WebSocket-соединение получает
60-секундную сессию в Redis, обновляемую каждые 15 секунд. После аварии исчезнувший
участник удаляется при следующей очистке истёкших сессий; это не мгновенная проверка.
Пустая комната автоматически истекает. При недоступности Redis интерфейс показывает
«Участники: нет данных», а не ложный ноль. Старые строковые счётчики не используются.

Медленный клиент или переполнение очереди приводят к переподключению и сверке,
а не блокировке всех комнат. При остановке сервера закрываются подписки и WebSocket.

Дополнительный тест PostgreSQL создаёт отдельную схему и удаляет её после проверки.
Он запускается только при явном задании `COLLABLEARN_TEST_DATABASE_URL`
(PostgreSQL URL изолированной тестовой базы):

```bash
go test ./internal/database -run TestPostgresConcurrentRevisions -v
```

Большинство Redis-проверок использует `miniredis` — модель Redis с настоящим TCP-клиентом
и Lua. Дополнительная проверка двух экземпляров с нативным Redis запускается при
`COLLABLEARN_TEST_REDIS_ADDR=127.0.0.1:6379` (отдельный тестовый Redis без авторизации):

```bash
go test ./internal/websocket -run TestNativeRedisTwoNodeDelivery -v
```

В GitHub Actions проверки запускаются с отдельными PostgreSQL 15 и Redis 7,
а также с `go test -race`. Отдельная задача собирает реальный Docker-образ и проверяет
запуск Compose, API, статические файлы, отказ/возвращение зависимостей и сохранность
документа после перезапуска. Секреты приложения и развёртывание в CI не используются.

## Конфигурация

Сервер читает переменные окружения. В Compose хосты зависимостей задаются автоматически;
`.env` используется самим Compose для подстановки пароля, имени базы и внешнего порта.

| Переменная | По умолчанию | Описание |
|----------|---------|-------------|
| `DB_HOST` | localhost | Хост PostgreSQL; в Compose `postgres` |
| `DB_PORT` | 5432 | Порт PostgreSQL |
| `DB_USER` | collablearn | Пользователь БД |
| `DB_PASSWORD` | обязателен | Пароль БД, без встроенного значения |
| `DB_NAME` | collablearn | Имя БД |
| `DB_SSLMODE` | disable | `disable`, `require`, `verify-ca`, `verify-full`; для внешней БД настройте TLS |
| `REDIS_HOST` | localhost | Хост Redis; в Compose `redis` |
| `REDIS_PORT` | 6379 | Порт Redis |
| `PORT` | 8080 | Порт приложения |
| `HTTP_HOST` | 0.0.0.0 | IP/localhost для HTTP-сервера |
| `STARTUP_TIMEOUT` | 45s | Общий срок подключения, миграций и подтверждения подписки, от 1s до 5m |
| `PUBLIC_ORIGIN` | пусто | Внешний origin за HTTPS-прокси, например `https://learn.example.org` |
| `APP_BIND_ADDRESS` | 127.0.0.1 | Только Compose: адрес публикации на хосте |
| `APP_PORT` | 8080 | Только Compose: внешний порт приложения |

Сервер повторяет подключения в пределах `STARTUP_TIMEOUT`; ошибка миграции
останавливает запуск. Миграции встроены в бинарник и выполняются в одной транзакции
с PostgreSQL advisory lock для одновременного запуска нескольких экземпляров.
SIGINT/SIGTERM закрывает WebSocket и завершает HTTP-запросы в пределах 30 секунд.

`/health` и `/livez` — проверка работы HTTP-процесса. `/readyz` за срок до двух секунд
проверяет PostgreSQL, Redis и жизненный цикл WebSocket hub: 200 при готовности,
503 при сбое или остановке. Это не проверка каждого сообщения Pub/Sub и не механизм
перезапуска Docker: состояние `unhealthy` само по себе контейнер не перезапускает.
Docker использует команду `/app/collablearn healthcheck`; образ работает от UID 10001
с файловой системой только для чтения.
