# Модель доступа к доскам

Статус: согласовано с владельцем проекта 31 октября 2026 года в issue
[#11](https://github.com/YaMosly/collab-learn/issues/11).

## Решение

Сохраняем текущую модель: **любой обладатель ссылки на доску может читать
и редактировать её**. Доска отсутствует в публичном каталоге. Для доступа достаточно
знать её ID — случайный UUID v4, используемый в ссылке и API.

| Действие | Правило |
|----------|---------|
| Создать доску | Доступно посетителю в пределах текущих лимитов запросов |
| Прочитать и изменить существующую доску | Доступно любому, кто знает её ID |
| Получать обновления WebSocket | Те же права на доску; действуют проверки Origin и лимиты |
| Поделиться доступом | Передать ссылку на доску |
| Хранить недавние доски | Локальный список браузера; он не подтверждает владение |
| Скачать текущий HTML/CSS | Из открытого редактора, в том числе с неподтверждёнными правками |

Создатель не получает отдельной административной роли. Аккаунты, разделение
читатель/редактор, управление приглашениями и индивидуальный отзыв ссылок
на этом этапе не вводятся. Передача ссылки передаёт полный доступ к документу;
запретить одному её обладателю редактирование отдельно от остальных сейчас нельзя.

## Существующие доски

Все существующие ID и ссылки остаются действительными. Переход между
`/?board=<id>` и `/#board=<id>` сохраняет доступ. Миграция данных или прав
не требуется. Не назначаем владельцем первого посетителя старой доски:
текущая схема не хранит доказательства владения.

## Границы текущей защиты

Общий каталог закрыт, Origin проверяется для браузерных запросов, частота запросов
ограничивается через Redis. Ссылки/ID исключены из access log приложения;
`Referrer-Policy` запрещает передачу Referer. Это дополняет модель доступа по ссылке,
но не устанавливает личность пользователя. Настройки журналов прокси остаются
частью развёртывания.

Проверяемые точки реализации: [HTTP-обработчики](../internal/handlers/board.go),
[WebSocket](../internal/websocket/client.go),
[Origin и лимиты](../internal/access/access.go).

## Если модель понадобится изменить

Нужна отдельная задача согласования владельца доски, ролей, приглашений,
совместимости старых ссылок и восстановления потерянного доступа. При такой
реализации проверка прав должна охватывать каждый HTTP-запрос и WebSocket,
включая уже открытые соединения после отзыва доступа. Эти границы соответствуют
рекомендациям [OWASP Authorization](https://cheatsheetseries.owasp.org/cheatsheets/Authorization_Cheat_Sheet.html)
и [OWASP WebSocket Security](https://cheatsheetseries.owasp.org/cheatsheets/WebSocket_Security_Cheat_Sheet.html).

До нового согласованного решения сохраняется описанное выше поведение.
