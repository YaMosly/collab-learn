# Работа над CollabLearn

Развиваем приложение небольшими законченными этапами. Основная актуальная версия
находится в `main`; ветки не используются как очередь готовых изменений.

## Задачи

Перед существенным исправлением или функцией найдите существующую issue либо
создайте новую: проблема, ожидаемый результат и критерии готовности.
Для небольшой правки достаточно ссылки на существующую задачу.

Текущие следующие этапы:

- [#11 — согласование прав чтения и редактирования](https://github.com/YaMosly/collab-learn/issues/11).

## Изменения и ревью

1. Сделайте один логический этап с понятным результатом.
2. Выполните проверки по затронутой функциональности и просмотрите итоговый diff.
3. Для небольшой проверенной правки допустим коммит непосредственно в `main`.
   Для крупного или рискованного изменения используйте короткоживущую ветку и PR
   в `main`, завершив его слияние после проверок в рамках того же этапа.
4. Свяжите коммит/PR с issue: `Refs #N` для части работы, `Closes #N` только
   при выполнении всех критериев. После прямого коммита закройте задачу,
   опубликовав ссылки на коммит, ревью и результат проверок.
5. Self-review автора обозначайте явно. Это не независимое одобрение.
   В PR используйте review; для прямого коммита результат можно записать в issue.
6. После push проверьте GitHub Actions. Отработанные ветки удаляйте после
   подтверждения включения изменений в `main`.

## Проверки

Клиентские сценарии и синтаксис:

```bash
node --test tests/*.test.cjs
node --check web/static/js/app.js
node --check web/static/js/document-sync.js
node --check web/static/js/board-history.js
node --check web/static/js/retry-policy.js
node --check web/static/js/source-export.js
node --check web/static/js/panel-layout.js
python tools/vendor-codemirror.py --check
```

Go:

```bash
go test ./...
go vet ./...
```

Интеграции PostgreSQL/Redis и `go test -race` выполняются в GitHub Actions
на выделенных сервисах. Отдельная CI-задача собирает Docker-образ и проверяет
Compose, API, WebSocket, ограничения запросов и восстановление зависимостей.
Локальный пропуск интеграции нужно указывать в результате проверки.

Для изменений интерфейса проверяйте затронутый сценарий в браузере.
Не включайте `.env`, секреты, пользовательские доски и приватные журналы в задачи,
коммиты или примеры воспроизведения.
